## 5. Notable defects found & fixed by tests

1. `updateVisit` overwrote omitted fields (partial-update merge implemented).
2. `listSuppliers` had broken `COALESCE(SUM(...))` SQL — suppliers screen would have crashed.
3. Patient profile `age` ignored DOB when stored age was null.
4. `checksums.mjs` used `new URL().pathname` (invalid on Windows).
5. Missing `build/icon.ico` (multi-resolution ICO 16→256 now generated + guarded by a test) and missing `assets/icons/app-icon.png` referenced by the main window.
6. E2E launch path made `app.getAppPath()` resolve incorrectly (packaged app unaffected; test harness fixed).

## 6. Known limitations (documented, not silent)

- DB not encrypted at rest → rely on OS disk encryption + auto-lock (`docs/SECURITY.md`).
- Installer unsigned (no code-signing cert) → verify via published SHA-256.
- Rows 42–44, 57 of the traceability matrix are manual UI QA / OS-level checks.
- E2E full journey requires the activation secret (`DENTIVA_ACTIVATION_SOURCE`) to be configured in repo Actions settings; the activation gate test always runs.
